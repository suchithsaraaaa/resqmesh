# ResQMesh AI: Release Numbering & Versioning System

This document outlines the versioning policy, naming conventions, and complete release history for **ResQMesh AI** standalone Windows installers.

---

## 1. Versioning Scheme: Semantic Versioning (`vMAJOR.MINOR.PATCH`)

ResQMesh AI uses standard **Semantic Versioning** for all production installer artifacts:

$$\text{v}\mathbf{MAJOR}.\mathbf{MINOR}.\mathbf{PATCH}$$

- **MAJOR (`X.0.0`)**: Substantial architectural overhaul or breaking protocol format changes (e.g. wire format protocol updates requiring all nodes to upgrade).
- **MINOR (`1.X.0`)**: New features, new UI dashboards, or new protocol extensions that remain backwards compatible with existing nodes.
- **PATCH (`1.0.X`)**: Bug fixes, performance optimizations, startup speed improvements, and asset resolution patches.

### Installer Executable Naming Convention:
All compiled installers are placed in the `release/` directory with the following standardized name:
```
release/ResQMeshAI-Setup-v<MAJOR>.<MINOR>.<PATCH>.exe
```
*Example*: `release/ResQMeshAI-Setup-v1.0.1.exe`

## 3. How to Deploy a Specific Version on Multiple Laptops

To ensure seamless peer-to-peer mesh compatibility, always use the latest release across all test laptops:

1. Locate the latest executable in `release/`:
   ```
   d:\Final_year_project\release\ResQMeshAI-Setup-v1.0.27.exe
   ```
2. Copy `ResQMeshAI-Setup-v1.0.27.exe` onto your USB drive or VM shared folder.
3. Run the installer on both machines (Host and VM).
4. Run the application — both nodes will be running identical protocol versions and will discover each other immediately.
